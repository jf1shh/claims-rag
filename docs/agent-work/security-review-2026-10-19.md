**Verified OK**
- **Engine allowlist:** enforced twice (api.py:213 and the router). The LLM, JWKS, reranker and S3 endpoints come only from config, so client input can't choose an outbound URL.
- **Simulation:** the stream path re-checks `simulation_mode`.
- **Filesystem paths:** `safe_filename` (basename, rejects `.` and `..`) and `LocalDocumentBlobStore._path` (resolve and containment check) cover upload, delete, download and staging. S3 keys reject `..`, empty segments and leading `/`.
- **Download headers:** Starlette writes CRLF or quote characters in filenames as `filename*=utf-8''…` (checked at runtime), so Content-Disposition can't be injected. Responses also set `nosniff`.
- **SQL:**
  - All SQLite and Postgres SQL is parameterized.
  - FTS5 tokens are alphanumeric-filtered and quoted.
  - The bandit B608 flag at job_store.py:151 is a false positive: column names are checked against `_UPDATABLE_FIELDS` and the values are bound.
- **Claim ACLs:**
  - Content, download, claim listing, chat, stream, eval and jobs all check the claim ACL.
  - Searches with no claim are limited to global documents (SQLite vector mask and FTS predicate, Postgres predicates), and `/api/documents` lists only global documents.
  - Staging/production without `CLAIM_ACLS_FILE` deny adjusters.
- **Development auth:** the development authenticator rejects any environment other than development/test, and production config forbids both the development provider and simulation.
- **OIDC:** RS256 only; exp, sub, iss and aud are required; error messages are generic.
- **Upload bounds:**
  - Body size is capped both by declared Content-Length and while streaming.
  - Uploads are read with `read(max+1)`.
  - Zip entry count and declared size are checked.
  - The parser runs in a subprocess with a wall timeout and a 2 GiB `RLIMIT_AS`.
  - Text is decoded with a bound.
  - Parser crashes and timeouts become 400/413, not 500.
- **Rate limiter:** keyed on tenant:subject (not X-Forwarded-For) and locked.
- **CSRF on JSON routes:** FastAPI 0.139's `strict_content_type=True` keeps the JSON endpoints from being driven by cross-site `text/plain` requests.
- **Error handling:**
  - The generic 500 handler and the `ChatClientError` texts reveal no internals.
  - Health checks report only exception type names.
  - The stream turns pipeline failures into a final error event.
- **Audit log:** written as JSONL with `json.dumps`, so it can't be log-injected, and question/answer text is stripped.
- **Frontend XSS:**
  - `formatMarkdown` escapes before formatting.
  - Filenames, claims, sources, pipeline logs, the modal and the prompt preview use `textContent`/`innerText`/`escapeHtml`.
  - Only object URLs go into `img src`.
  - The token is kept in `sessionStorage`.
